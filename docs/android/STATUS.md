### M1 decisions made after the plan
- **Strokes on the wire, server renders.** Producers send vector strokes (`SketchPayload`). Core plans the pages; resvg renders PNG for the model and SVG for the UI.
- `perfect-freehand@1.2.3`, pinned exactly. The same outline options are used client and server (`sketchStrokeOptions`).
- **Limits:** 3,000 strokes · 250k points · 4 MB per sketch. At most 6 pages, page long edge ≤ 2000 px.
- **Kept practice page:** a dock submit with unsent ink shows a removable "Sketch attached" chip. A re-submit with no new ink sends only a reference. After a reload, restore the submitted strokes (server) plus unsent ink (localStorage). This lands in M3.
- **Sketch view keys:** Ctrl/⌘+Enter submits, Esc closes (cancels dictation first), Ctrl+Z / Ctrl+Shift+Z undo and redo. Plain Enter does nothing.
- **Unsent ink (M1):** closing the sketch view keeps the ink in memory for that question or problem (`components/sketch/ink-memory.ts`); a submit from the canvas clears it. A plain text submit from the dock leaves the ink alone (the "Sketch attached" chip is M3).

### M2 (transcribe-first): implemented 2026-10-26, plan approved by the owner
Owner decisions: the dispute is a new recorded `dispute` input, available only when idle with no question waiting; the card heading is "I read:" (model-neutral); the tool field is `reading` (not the plan's `latex`, since diagrams get a structural reading); gate = the active problem's newest sketch only, `solvedWithHints` counts as solved.
- `src/agent/tools/sketch.ts` `read_sketch {sketchId, reading, uncertain[]}`: always registered (prober, teacher, practice, placement; practice builds its own with the gate). It checks the id against the transcript's sketches; the call and its clean result are the record, no new store.
- `src/core/sketch-gate.ts` (pure): `sketchStatesOf` (read/dispute fold), `sketchGateOf` / `noteSketchRead` / `sketchConcludeProblems` (the conclude gate; a closure on `PracticeGate`, so a `[read_sketch, conclude]` batch works), `sketchReplayPlan` (elision), `sketchIdsOf`.
- Gate: `conclude` as solved/solvedWithHints is refused (an error result: never mastery evidence) while the newest sketch on the active problem is unread, doubtful, or disputed. movedOn/surrendered/dismissed are never gated.
- Dispute: new `dispute {sketchId, text?}` input (400 unless the sketch was read and no question is waiting) → `sketch-dispute` marker (content tells the model to re-read; details `{sketchId, text?}`); folds into the gate; transcript line `SketchDisputeLine`.
- Card: `components/artifacts/read-sketch-card.tsx` (registered as `read_sketch`): thumbnail, "I read:", the reading in math, doubts, "That's not what I wrote" (optional "What did you write?"). The button shows only on the newest reading, only after the call has a result, only while idle (`ChatActionsContext.sketchDispute`).
- Prompt `shared/18-sketches.md` (composed into all four agents; pin test updated); sketch answers' `next` text and the practice marker's line say "call read_sketch first".
- Elision (per OCCURRENCE: a submission, an answer, or a dispute marker re-sending the sketch): an occurrence rides as a text stub (`sketchStubText`, label first) once a clean, doubt-free `read_sketch` follows it AND its scope has closed (a clean problem pose / a later non-dismissed question answer after it). Both conditions are "an event after this occurrence", so it is ONE-WAY: it never flips back to an image. Only clean results count (a refused pose or a prose-gate-blocked quiz closes nothing). The 20-page window stays as a backstop.
- Disputes: a dispute does NOT re-open the old pages. `toLlmMessages` attaches the disputed sketch's pages to the dispute marker's own (new) message, so a live `claude` process, which only receives new messages, gets the image; that copy is stubbed by the same rule once a clean read follows it and the scope closes. (Review finding: without this, a dispute after elision told the tutor to re-read a page it never received.)
- Fingerprint (`claude-code.ts` `fingerprintBlocks`): a sketch page hashes by its label whether image or stub, so a form change never respawns a live process; this also removes the respawn the 20-page window caused. Regression test: a fresh process whose replay carried the sketch as a stub still gets the page with the dispute, on the same pid.
- Compaction summaries: `[sketch sk_x — read as: …]` / `— not read]`. `skills/learnharness` documents sketches and the dispute/read markers; its reader knows `read_sketch` and `sketch-dispute`.
- Tests: `tests/sketch-reading.test.ts`, `tests/read-sketch-card.test.tsx`, additions in `practice-flow` (gate + dispute through the real handler), `session-core`, `courses`/`tool-toggles-bridge`/`practice-agents` (tool-list pins), `prompt-overrides`. `npm run typecheck`, `npm run lint` clean; `npm test` 2370/2380, the 10 failures are the known Windows ones (one more auth test flaked once under full-suite load and passes alone).

- **Tall page:** a viewport-sized sticky canvas redrawn under the scroll offset (no page-tall backing store). Room below the lowest ink, up to 12000 px. - **Kept page (practice problems only; a question is answered once):** `components/sketch/ink-memory.ts` holds the kept page (submitted strokes, drawn dimmed and locked) and the unsent ink on top (memory + localStorage `lh:ink:<key>`). A submit sends the WHOLE page: new `SketchPayload.newFrom` marks where the new ink starts and `planSketch` draws a blue "[" bracket in the left margin over those rows (page sizes unchanged). After a reload the kept strokes come from the server (`GET /api/chats/[id]/sketches/[sketchId]/strokes`, `useKeptPage`); `keptSketchOf` (core) finds the problem's newest sketch.

With new ink the text submit sends the whole page; with none it sends only the id: `thinking.sketchRef`, resolved by the server against the stored strokes (`resolveSketchRef`; unknown id → 400; stored pages are not rewritten). Removing the chip sends the text alone; opening the sketch view re-attaches.

In choice modes the box holds the options, I don't know / Other, and the confidence stops (`sketch-choices.tsx`), bound to the dock's own `sel` / `confIdx` / `other`; the sketch rides as thinking, the pick stays the answer.
